## 3. 검정력 — 풀링 회귀(주 목표): 봇Δ→유저Δ 환산 기울기

방법: 레벨 i마다 (봇Δ_i, 유저Δ_i) 쌍을 얻어 유저Δ = β0 + β1·봇Δ + ε 회귀. 봇Δ는 이미 알려진 값(고정 x), 유저Δ 분산 = 2·p0·(1−p0)/n_i(그 레벨 군당). 레벨마다 n_i가 다르면(실제로 구간별로 크게 다르다, §3-1) **역분산 가중** 회귀로 합산: Var(slope) ≈ 1 / (sd(봇Δ)² · Σ_i w_i), w_i = n_i / (2·p0_i·(1−p0_i)).

- 판정 기준(예시): slope=0.5(봇Δ의 절반만 유저에게 전달)를 0과 구별하려면 SE(slope) ≤ 0.179. slope=1.0(1:1 전달) 구별은 SE(slope) ≤ 0.357.
- 봇Δ 표준편차 가정: R2 선별 바깥 칸 Δ 중앙값 0.16~0.20, 문턱 0.13 근처 밀집(10_dda_set_preparation.md §10-1 "선택 편향 — 재측정 시 평균 회귀") → **보수적으로 0.05~0.10**로 스캔.

### 3-0. 참고 — 레벨마다 n이 같다고 가정하면 (단순화, 실제 계획 아님)
| 레벨 수 | 봇Δ sd=0.05 | sd=0.08 | sd=0.10 |
|---|---|---|---|

| **파일럿 군 식별**(어느 판이 control/variant였는지) | ❌ 없음 | 지금 L32+ 는 전부 명시 타일(t0 0칸)이라 변형 자체가 존재하지 않음. 파일럿 전용 **최소 파라미터**(토큰 전체 체계 아니어도 control/variant 1비트) 필요 — §8-① |
| 24h 복귀율(가드레일) | ✅ 계산 가능 | 기존 AF 이벤트로 기기별 다음날 활동 여부 산출 가능(판 이벤트 timestamp만 있으면 됨), 신규 이벤트 불필요 |
| `level_quit`(K1, 포기/강제종료 구분) | ❌ 없음(정본도 "선택", 미출시) | 가드레일 정밀도 개선용. 없어도 `no_end`(포기+강제종료 합산)로 근사 가능 — 파일럿 **필수는 아님** |

## 8. 게임팀 요청 목록 (파일럿 실행 전 필요, 승인·구현은 게임팀)

1. **파일럿 전용 강제 배정 하니스**: 고정 레벨 목록(20~25개)에 한해 `LoadLevel`에서 해시(CUID+level_id)%2 로 원맵(`level_N`) vs 지정 변형 행(`seedvar_N`, 고정 토큰 1개)을 로드. 정본 §V2-9-2 ③과 같은 "3필드만 교체" 지점 재사용 — 사다리(점수·완화·상승) 로직 없이 동작하는 **축소판**(U1~U4 사다리 상태 머신 불필요, P1 전체보다 작음).
2. **최소 식별 파라미터**: `level_start`/`level_clear`/`level_fail`에 파일럿 군 값(예: `control`/`variant`) 1개 파라미터 추가 — 정본 §V2-4 K2(`seed_variant`)의 축소판으로 재사용 가능.
3. (권장, 필수 아님) `level_quit`(K1) — 포기/강제종료 구분, 가드레일 정밀도 개선.
4. **사다리(P1 클라)와 겹치지 않는다는 보장**: 사다리가 먼저 출시되면 파일럿 대상 레벨을 사다리 평가에서 빼거나 파일럿을 사다리 출시 전에 끝낼 것(§4 충돌 명시 참고).
5. AF 파라미터 한도 확인(이벤트당 25개 Firebase 상한 — 정본 §V2-4 가 "범위 안"이라 보고했으나 파일럿 전용 1개 추가도 같은 한도 안인지 최종 확인).
