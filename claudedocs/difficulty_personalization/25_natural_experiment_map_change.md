# 25. 자연 실험 — 앱버전별 맵 다른 레벨로 본 봇Δ→유저Δ 환산

> 작성 2026-10-15 · 브랜치 `feature/pv-seed-variants`. 라이브 A/B 없이, 기존 AF 데이터 안에서 "같은 레벨
> 번호인데 앱버전에 따라 맵이 달랐던" 20개 레벨(`map_match="mixed"`)을 자연 실험으로 써서 봇이 예측한
> 맵간 클리어율 차이(봇Δ)가 실제 유저 차이(유저Δ)로 얼마나 환산되는지 추정한다. 24_live_pilot_design.md가
> 설계한 라이브 파일럿과 같은 통계 방법(역분산 가중 풀링 회귀)을 **이미 있는 데이터**에 적용한 것.
> 재현: `backend/scripts/natural_experiment.py af|maps|run|report`. 산출 `backend/data/pv_sandbox/af_calibration/natural_exp/`.

## 1. 방법

1. **유저Δ**: `level_metrics.json`(기존 af_level_metrics.py 산출물, CSV 재처리 없음)의 `clean_ft_by_version`에서
   구맵(android 1.0.162, n=1,671~11,286/레벨) vs 신맵(android 1.1.0 + ios 2.1.0 합산, n=482~2,544/레벨) 클리어율 차이.
2. **시간 드리프트 보정**: 같은 두 버전 구간에서 맵이 안 바뀐 11개 대조 레벨(`map_match="same"`)의 역분산
   가중평균 차이 = **+0.27%p**. 전부 mixed 레벨 유저Δ에서 빼서 `diff_corrected` 사용. (test-retest 문서 22의
   드리프트 추정 2.0~2.6%p보다 작음 — 비교 구간이 더 짧고 버전 2개뿐이라 직접 비교는 아님.)
3. **맵 pull**: 구맵 = 게임 저장소 커밋 `a2229a5d`(android 1.0.162 빌드 샤드), 신맵 = `b741f6a3`(android
   1.1.0 / ios 2.1.0 빌드 샤드 = 에디터 LIVE3와 동일) — `git show`로 읽기만, 저장소 수정 없음.
4. **변화 종류 분류**: 두 맵의 구조 해시(`canonical.py struct_hash`, 타입 제외)가 같으면 `tile_only`.
   다르면 위치별로 effect·컨테이너(stack/craft 등) 차이가 있으면 `gimmick_changed`, 없으면(칸 수·배치만
   다름) `layout_changed`. (레벨 행 메타 `useTileCount`도 다수 레벨에서 같이 바뀜 — 버전 간 밸런스 조정이
   맵 교체와 같이 들어간 것으로 보임, row_changed 필드에 기록.)
5. **봇Δ**: 봇 v2.3(`bot_version="v2.3"`, 전 parity 항목 켬, 보스 레벨은 `auto_collect` 로우값 적용),
   θ ∈ {0.65, 0.75, 0.85}(14_bot_v2_vs_af_L1_31.md L1~31 보정 θ 근방) 평균, 레벨·맵당 1,152~1,200판
   (요구한 ≥400 충족). randSeed=0 레벨은 클라 `ShuffleEmptyTiles` 포트로 32배치 샘플.
6. **회귀**: 유저Δ = β0 + β1·봇Δ, 가중 = 1/Var(유저Δ)(봇은 n이 커서 거의 고정값 취급 — 24_live_pilot_design.md
   §3와 동일 방법). CI는 t분포(df=n−2).

## 3. 결론·시사점

- **방향은 통계적으로 유의하게 전달된다**(CI가 0을 배제, 부호일치 80%) — 봇Δ가 완전히 무작위 노이즈는
  아니라는 근거.
- **크기는 크게 압축된다**: 점추정 0.155, 넉넉히 잡아도 CI 상한 0.280. DDA 시드 변형 선별 문턱
  \|봇Δ\|≥0.13은 유저 체감으로 **대략 1~4%p** 수준일 가능성 — "봇Δ 그대로 유저 체감"이라는 가정은 과대.
- **기믹 변경(craft/ice 추가·이동 포함) 레벨은 부호 일치가 완벽(6/6)**하고 레이아웃만 바뀐 레벨은 상대적으로
  약함(69%, CI가 0 포함) — 다만 각각 n=6·13이라 이 차이 자체가 유의한지는 판단 불가.
- **타일만 바뀐 사례가 L1 하나뿐이고 양쪽 100% 천장**이라, DDA 시드 변형(타일 타입만 바뀌는 case)과
  가장 가까운 비교는 이 자연실험에서 **거의 못 건졌다**. 이 연구가 다루는 "mixed" 20레벨은 전부 L1~31
  (튜토리얼, 고정 레이아웃 코드 구간)이고 주로 레이아웃·기믹 차이라 시드 변형(L32+, 타입만 바뀜)과
  성격이 다르다 — **외삽 신뢰도는 제한적**.
- **24의 라이브 파일럿 규모를 줄일 근거는 약하다**: 방향 전달 자체는 추가 확인됐지만(파일럿 판정기준 중
  "부호일치 ≥70%"는 이미 이 자연실험에서도 80%로 충족), 기울기 CI가 넓고(0.03~0.28) 시드 변형과
  성격이 다른 레벨(레이아웃/기믹 위주)에서 나온 값이라 **기울기 추정 자체를 대체하긴 부족**. 다만
  "slope=1.0(1:1 전달) 가정은 기각된다"는 방향의 보강 근거는 된다 — 파일럿 표본설계(§3-2, sd(봇Δ)=0.08
  기준 slope 0.5/1.0 구별)를 유지할 근거.

## 4. 한계

- mixed 20레벨 전부 L1~31: 이 구간만의 특수성(고정 레이아웃, 튜토리얼 난이도 바닥효과 적음)이 다른
  구간에 일반화되는지 불명.
- 변화 종류 분류는 구조 해시 기반 자동 분류(효과·컨테이너 필드 차이 탐지)로, 게임 밸런스 의도까지 보지
  않음 — `useTileCount` 행 값도 같이 바뀐 레벨이 다수라 "맵만" 바뀐 게 아니라 "레벨 설계"가 통째로
  바뀐 경우가 많다(생성 난이도 조정과 맵 교체가 같이 들어간 것으로 보임).
- 봇 θ는 L1~31 구간의 과거(v1/v2) 보정값 근방을 그대로 사용 — v2.3 전용 재보정 아님.
- 회귀는 봇Δ를 고정값으로 가정(실제로는 레벨·맵당 1,152~1,200판 표본오차가 있음) — errors-in-variables로
  기울기가 실제보다 작게 추정될 수 있음(과소추정 방향).
