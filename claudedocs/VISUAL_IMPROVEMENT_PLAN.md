# 비주얼/타일배치 개선 계획 (모양·÷3·뭉침·7×7+레이어)

> 2026-06-17 작성. 난이도/솔버블 검증은 개선됐고(역생성·A*), 다음은 **비주얼(타일 배치/모양)** 개선.

## 1. 현재 구조와 문제 (코드 확인됨)

| 영역 | 현재 동작 | 문제 |
|---|---|---|
| 그리드 사이즈 | 난이도↑ → grid 8×8까지 커짐 (`generate.py` grid_choice) | 게임 플레이 시 타일이 너무 작아짐(7×7이 마지노선) |
| ÷3 보장 | 패턴은 positions만, ÷3 미보장 → 사후 `_finalize_divisibility_guarantee`가 타일 제거/추가 | 타일 누락·빈칸(비주얼 깨짐) |
| 패턴 다양성 | 수동 `data/custom_patterns.json`(265개) + 코드 `pattern_templates.py` | 손작업, 다양성 한계 |
| 타입 배치 | `select_color_balanced_tiles`는 "어떤 색 쓸지"만 균등 / 공간 배치는 무작위 | 같은 타입 뭉침 |

핵심 제약(코드):
- `GenerateRequest.max_layers`: `ge=1, le=7` (스키마 캡)
- OOB/경계 처리에 `range(7)`/`range(8)` 하드코딩 (`generator.py` 1090, 9454, 9488)
- 봇(`bot_simulator`)은 동적 `num_layers` 지원 → 레이어 수 늘려도 시뮬은 동작
- 패턴 데이터 구조: `"{idx}_{cols}x{rows}": {grid_size, positions:[...], count}` — **위치만, 타입 없음**

## 2. 개선 3축

### 🅐 7×7 캡 + 레이어 기반 난이도 (토대)
- grid_choice를 **최대 7로 캡**: S/A=5~6, B=6~7, C/D/E=7
- 줄어든 타일 수를 **레이어 층수로 보충**: DIFFICULTY_PROFILES의 max_layers 상향, 스키마 캡(le=7) 상향, OOB range 하드코딩을 동적 num_layers로 교체
- 난이도 = (7×7 면적 고정) × (레이어 수) × (블로킹 강도)
- 역생성/솔버블 검증이 깊은 스택의 데드락을 방어 → 궁합 좋음
- ⚠️ 클라이언트(Unity)가 >7 레이어 렌더링 지원하는지 사용자 확인 필요(같은 7×7 footprint에 깊이만 증가)

### 🅑 절차적 패턴 생성기 + 큐레이션 UI (÷3 보장 + 다양성)
**🅑-1 백엔드** (`/api/patterns/generate`)
- 입력: **최대 그리드 사이즈**(≤7), 복잡도(채움률·구멍), 대칭 모드(수평/수직/4방/회전), 후보 수 N
- 처리: 대칭 기반 셀 선택 → **÷3 보장**(대칭 단위 개수 정정) → 미적 점수(대칭·연결성·빈공간 분포) 랭킹
- 출력: 후보 N개 `positions` + 점수 + grid_size (타입 없음)

**🅑-2 큐레이션 UI** (패턴 에디터 확장 또는 신규 패널)
- 최대 그리드·옵션 설정 → [생성] → 후보 **렌더링 미리보기** → 각 후보 [채택]/[폐기]
- 채택분만 `custom_patterns.json`에 저장(라이브러리 확장) → 레벨 생성이 확장 라이브러리에서 선택
- 미리보기: `frontend/src/utils/levelPreview.ts`를 positions 전용 경량 렌더로 변형 재사용
- 효과: AI가 다양한 ÷3-valid 모양 제안 → 사람이 눈으로 좋은 것만 채택(품질 통제)

### 🅒 자연스러운 타입 공간 배치 (뭉침 해소)
- 타입 선택(색균등)은 유지, **공간 배치에 분산 제약**: 같은 타입 인접 뭉침 방지(블루노이즈/그래프컬러링/제약충족)
- 역생성(witness)은 솔버블 우선이라 타입 고정 → "동일 솔버블 그룹 내 위치 셔플"로 자연스러움만 추가
- 일반 생성 경로엔 분산 배치 알고리즘 적용

### 🅐 구현·검증 결과 (2026-06-17)
- **parity 보정**: grid_size는 *홀수 레이어* 기준이고 짝수 레이어는 +1 → 가시 최대 = grid_size+1.
  따라서 `LEVEL_CONFIG_TABLE.grid_size`와 `generate.py` grid_choice를 **최대 6**으로 캡(= 가시 7×7).
  (계획서의 "grid_choice 7 캡"을 parity 때문에 6으로 정정)
- **레이어 상향**: LEVEL_CONFIG_TABLE max_layers (61-100:6, 101-225:7, 226-600:8, 601-1125:9, 1126+:10),
  내부 난이도 클램프 B≤6/C≤8/D·E≥7, DIFFICULTY_PROFILES(validated) D 7-9/E 9-11,
  스키마 `max_layers`/`active_layer_count` le=7→le=12, OOB `range(7)`/`range(8)`→`range(15)`.
- **측정 (level_number별 생성→솔버블/봇)**:
  | 레벨 | 가시 grid | 레이어 | ÷3 | A* | 비고 |
  |---|---|---|---|---|---|
  | 30 | 6×6 | 3층 | ✓ | PROVEN_SOLVABLE | |
  | 80 | 7×7 | 4층 | ✓ | PROVEN_SOLVABLE | |
  | 300 | 7×7 | 6층 | ✓ | PROVEN_SOLVABLE | |
  | 700 | 7×7 | 6층 | ✓ | PROVEN_SOLVABLE | |
  | 1200 | 7×7 | 7층 | ✓ | UNCERTAIN(60s) | 역생성 봇클리어 avg60%/opt39% |
  | 1500 | 7×7 | 7층 | ✓ | UNCERTAIN(60s) | 역생성 봇클리어 exp/opt 100% |
- **결론**: 가시 ≤7×7 달성, 난이도 레이어로 확보(3→7층), ÷3 전 구간 유지. 얕은 레벨은 A* 증명,
  깊은(7층) 레벨은 상태공간이 커서 A* 60s 미증명(UNCERTAIN)이나 ÷3 보장 + 역생성 constructive
  witness + 봇 클리어(rate>0)로 플레이 가능 확인.
- ⚠️ **미해결 사용자 확인 필요**: Unity 클라이언트가 동일 7×7 footprint에 7~10 레이어 깊이 렌더링을 지원하는지.

### 🅑 구현·검증 결과 (2026-06-17)
- **백엔드** `app/core/pattern_synth.py` (신규): 대칭(상하좌우/4방회전/좌우/상하/점대칭) 기반
  절차 생성 + 전략(blob/diamond/ring/random/frame) + **÷3 강제 보정**(돌출부 제거 우선) +
  단일홀 메움 + 미적 스코어(대칭40·연결25·solidity25·채움10) + Jaccard 다양성 선택.
- **엔드포인트** `analyze.py`:
  - `POST /api/patterns/synthesize` — 후보 N개(positions+미리보기 grid+점수). 모두 ÷3 보장.
  - `POST /api/patterns/accept` — 채택분을 custom_patterns.json에 저장(64+ 자동 인덱스, `synth:true` 표식).
- **자동 사용 통합** `generator.py`: `_get_synth_pattern_indices()`로 채택 synth 인덱스를
  `_generate_auto_layer_pattern_configs`의 top/medium/hard/middle 풀에 주입 → 일반 생성에서
  자동 채택. 크기 미스매치는 `_get_custom_pattern` size-fit fallback이 흡수(안전).
- **프론트** `PatternSynthModal.tsx` (신규) + PatternDebugPanel에 [🧩 절차생성] 버튼:
  최대/최소 그리드·대칭·후보수·채움률 설정 → 생성 → 후보 렌더링 미리보기 → 개별 [채택].
- **검증**: synthesize/accept 엔드포인트 동작, 명시 pattern_index=synth → 해당 모양 렌더 확인,
  synth 라이브러리 존재 상태 auto-mix 회귀(Lv30/300/700) 전부 ÷3 OK·≤7×7·PROVEN_SOLVABLE.
  tsc 통과, Vite 클린 컴파일. (Playwright MCP 미연결로 웹뷰 자동테스트는 생략)
- 테스트로 추가한 synth 패턴은 커밋 전 custom_patterns.json 원복(사용자가 UI로 직접 생성).

- **검증**:
