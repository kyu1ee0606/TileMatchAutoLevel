## 1. 배경 / 현재 동작 (확인된 코드)

보드 타일 = `"t0"`(런타임 랜덤) 또는 `"t1"`~`"t15"`(고정). top-level `useTileCount`(1~15) = 종류 수.

t0 확장 경로:
- `Assets/08.Scripts/Tile_Script/InGame/DB_Level.cs`
  - `ShuffleEmptyTiles()` (~L1104) → `DistributeTiles()`
  - L1110: `maxTileIndex = useTileCount > 0 ? useTileCount : maxTileIndex;`
  - `ColorCapacityOf(colorIdx, useTileCount) = Clamp(useTileCount - colorIdx*3, 0, 3)` (~L1215), `TilesPerColor=3`
  - 색0=t1~3 / 색1=t4~6 / 색2=t7~9 / 색3=t10~12 / 색4=t13~15

**현재 문제: t0는 항상 `t1..t{useTileCount}`만 사용** → useTileCount<13이면 t13~15 비주얼 구조적으로 못 씀. 배치와 비주얼이 한 시드에 묶여 있음.

기존 시드 패턴: 레벨 JSON에 `randSeed`가 **구체값**으로 박힘(예: `459838`). 인게임에서 시드 -1이면 매 실행 랜덤 동작이 이미 존재 → **이 시드 패턴을 비주얼에도 그대로 차용**.

---

## 2. 목표

t0 확장을 **2단계 분리**:
1. **배치/그룹** (어느 위치들이 같은 종류 = 매칭 트리플) → **기존 시드로 고정**. 솔버블·난이도 불변.
2. **비주얼 인덱스** (각 종류가 쓸 스프라이트 t1~t15) → **신규 "비주얼 시드"로 별도 결정**.

요구 동작:
- **구체 시드(>=0)**: 결정적 → **에디터 미리보기 == 인게임 표시** (동일 시드·동일 알고리즘).
- **-1 (예외)**: 런타임 랜덤. 매 실행 비주얼 다름. 에디터 미리보기는 "한 예시"일 뿐(불일치 감수).
- **없음/기본**: 현재 동작(비주얼=배치 인덱스 그대로) — **하위호환**.

---

## 3. 요구사항 — 맵 데이터에 비주얼 시드 필드

레벨/맵 데이터에 시드 필드 추가 (필드명 협의 가능, 예: `visualTileSeed`):
- `>= 0` : 해당 시드로 비주얼 인덱스 **결정적** 선정 (재현·에디터 일치)
- `-1`   : 실행마다 랜덤 (예외, 기존 스폰 시드 -1과 동일 의미)
- **없음** : 현행 동작 유지(하위호환)

### 동작 순서
1. 기존 로직대로 t0 → 종류(그룹) 배정 — **배치 시드 = 레벨 시드 고정** (난이도/솔버블 결정).
2. **비주얼 시드**로 `useTileCount`개의 **서로 다른** 스프라이트 인덱스를 t1~t15 풀에서 선택, 각 종류에 1:1 매핑.
   - useTileCount=6 이어도 풀이 t1~15 전체 → t13~t15 비주얼 등장 가능.

## 4. 🔴 핵심 선결조건 (이것만 지키면 성립)

> **에디터와 게임이 "시드 → 비주얼 인덱스" 선정 알고리즘을 100% 동일하게 구현해야 함.**

- 같은 시드 + 같은 알고리즘 → 같은 결과 → **에디터 미리보기 == 인게임** 보장.
- 게임팀: 알고리즘을 **명세로 공개** (의사코드/순서/난수 생성기 종류·시드 적용 방식).
- 에디터(요청측): 그 명세를 **그대로 복제** → 미리보기 일치.
- 비주얼 선정은 `(seed, useTileCount, 풀)`의 **순수 결정함수** — 다른 런타임 랜덤/시간/플랫폼 의존 섞지 말 것.

## 5. 반드시 지킬 불변식 (회귀 금지)

1. **distinct 보장**: 한 실행 안에서 서로 다른 종류 = 서로 다른 스프라이트 인덱스. (중복 매핑 = 가짜 매칭, 절대 금지.)
2. **배치 불변**: 비주얼 시드가 바뀌어도 "어느 위치가 같은 종류인지"(그룹 구조)는 변하지 않음 → 솔버블·난이도·봇 클리어율 동일.
3. **종류 수 불변**: distinct 종류 수 = `useTileCount` 그대로. 독(dock)/데드락 판정 영향 없음.
4. **하위호환**: 비주얼 시드 필드 없는 기존 레벨 = 동작 변화 0.
5. **명시 타일**(`"t13"` 등 직접 박힌 값)은 종전대로 그대로 렌더 (`Tile.cs:428` 변경 금지). 비주얼 시드는 **t0(랜덤)에만** 적용.
6. 키타일(t16)/`stack_`/`craft_` 특수타일 로직 불변.

## 8. 수용 기준 (테스트)

1. `useTileCount=6`, 보드 전부 t0, `visualTileSeed=12345`(구체) → **에디터 미리보기와 인게임 보드가 픽셀 동일**(같은 인덱스 세트), 6종 distinct, ÷3, 매칭/클리어 정상.
2. 같은 레벨·같은 구체 시드 두 번 실행 → 비주얼 동일(결정적).
3. `visualTileSeed=-1` → 실행마다 비주얼 다름, **배치(그룹 구조)는 매번 동일**(배치 불변 검증), 매칭 정상.
4. 비주얼 시드 필드 없는 기존 레벨 → 비포/애프터 보드 동일(회귀 0).
5. 명시 t13/t14 박힌 레벨 → 그대로 렌더(비주얼 시드 영향 없음).
