# 48. DDA 시드 규격 v2 (3×4) — ±1·±2 각 3시드 오프라인 준비 (2026-10-22)

> 사용자 지시(2026-10-22, Codex 경유): 쉬움 −2/−1, 어려움 +1/+2를 각 3시드로 준비한다(원본 포함 13종). 사용자가 서버에 새 컬럼 2개를 수동으로 추가할 예정이다. **이번 작업은 준비만 한다.**
> 하지 않은 것: 서버 읽기·쓰기(어떤 경로든), 구규격 업로드 재개, rollback, 봇·솔버·난이도 측정, 게임 저장소·Unity 수정, 자동 DDA ON, 커밋·push.
> 선행 문서: [46](46_dda_t0_all_levels_prep_20261020.md)(t0 준비·배정 정합), [47](47_dda_seed_editor_export_20261020.md) §13~14(구규격 일괄 업로드·보류).

## ⚠️ 게임 코드 미호환 경고
- 현재 게임 코드·검증기·콘솔은 시드 **정확히 5개**, **±1(ddaEasySeeds/ddaHardSeeds)만** 받는다. 이 규격(3개, ±2)은 게임 쪽 구현 전까지 쓸 수 없다.
- 게임 `sourceConditionHash`는 `행 − {map, ddaEasySeeds, ddaHardSeeds}`로 계산한다(게임 `tools/out/dda_runtime_t0_20261020_1601/README.md` :52, :91 "서버 행에 컬럼이 추가되면 조건 행 제외 목록 갱신 필요").
  - 서버에 `ddaEasy2Seeds`/`ddaHard2Seeds` 컬럼을 추가한 뒤 굽기를 하면, 행에 키가 늘어 **전 레벨 조건 해시가 어긋난다** → 게임 제외 목록을 4필드로 넓히기 전까지 DDA는 전부 원본으로 폴백한다.
  - 자동 DDA가 OFF라서 지금 플레이어 영향은 없다. 다만 게임 쪽 갱신이 선행 조건이다.

## 1. 필드 계약
| 필드 | 의미 | useTileCount | 값 |
|---|---|---|---|
| `ddaEasySeeds` (기존) | −1 | N−1 | 양의 Int32 3개, 쉼표 구분, 공백 없음 |
| `ddaHardSeeds` (기존) | +1 | N+1 | 같음 |
| `ddaEasy2Seeds` (신규) | −2 | N−2 | 같음 |
| `ddaHard2Seeds` (신규) | +2 | N+2 | 같음 |
- 원본 randSeed + 12개 = 레벨당 13종이 모두 다르다. 같은 레벨 안에서 배정 결과 맵(resolved map)도 모두 다르다.
- 필드 이름은 지시안 그대로 썼다. 다른 이름이 필요한 근거는 찾지 못했다.
- N, t0 계약, 조건 해시 공식은 문서 46 §3과 같다. 범위는 1~15이고 t0 세트 수를 넘을 수 없으며, easy는 2종 이상이어야 한다. 클램프는 하지 않았다(범위를 벗어나면 그 필드만 보류).

## 3. ±1 3개 선정
- **저장된 난이도 근거는 없다.** t0 N±1 변형은 측정된 적이 없다(문서 46 §1 "재사용 가능 측정 0", 설정 `difficultyRank: null`). 그래서 Δ·CI·순서 일관성으로는 고를 수 없었다.
- 저장된 근거로 쓴 것: 배정 정합 검사 결과(`assign_check_20261020_135511/per_variant.csv`, 설정별 PASS/FAIL, resolvedMapSha256)와 catalog v1 시드 순서.
- **선정 규칙**(±1·±2 공통, 사전 고정):
  1. 배정 정합 PASS
  2. resolvedMapSha256가 레벨 안에서 고유 (±1·±2 전체 공유)
  3. 위를 통과한 것 중 cand 순서(=추출 순서, 난이도와 무관)로 앞의 3개를 고른다. 3개 미만이면 그 필드를 보류한다.
- 결과: 후보 12160개 모두 PASS, 중복 맵 0 → 1216레벨 × 2방향 모두 유효. 결과적으로 **catalog 5개 중 앞 3개**다.
  - 이것은 규칙에 따른 결과일 뿐이다. 난이도 검증을 거친 선정이라는 뜻은 아니다.
  - 장점: 새 ±1 3개 = 구규격 서버 5개의 접두 3개 → 이관할 때 기존 값을 덮어쓰지 않아도 된다(§7).
