## 작업 순서 평가 (이득 ÷ 비용)
현 계획: serve+어댑터 → 생성기 막힘 검사 → 검증 루프·batch-verify → MC/RL/tune → solver.
- 앞 3개는 맞다(이득 큼·추가 비용 작음·프로필 검증 완료).
- **MC/RL/tune 과 solver 는 순서가 아니라 착수 여부부터** 재판정해야 한다: 서비스 MC 는 v1(롤아웃 없음)이라 절대 이득이 작고, solver 는 신규 알고리즘이며 목적이 판정 품질이다. 둘 다 "사용 빈도·필요성 측정 → 결정" 단계를 넣자.
- 수정 순서 제안: ⓐ 조기 중단(0.5~1, 엔진 무관) → ⓑ serve + 어댑터 + RNG 상태 전달 + `on` 스위치·폴백 계측(폴백 비율·C# 오류율 로그) → ⓒ 생성기 막힘 검사 `on`(짧은 shadow) → ⓓ 검증 루프·batch-verify·autoplay `on` → ⓔ **유휴 단독 속도 측정 1회**(현재 속도표 전부 부하 하 교대 측정) → ⓕ MC v1 / solver 는 수요 확인 후.
