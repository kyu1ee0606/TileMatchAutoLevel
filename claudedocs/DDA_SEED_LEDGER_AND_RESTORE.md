## 사용 순서
**업로드 전**
1. 맵툴 실행 → 제작 → 내보내기 탭 → GameBoost 연결 확인.
2. "라이브 전체 백업" 메모(예 `1.1.2 업로드 직전`) → [라이브 전체 백업 (읽기만)] → 완료 행 수·sha256·저장 경로 확인
   (불완전 백업이면 다시 시도). 마지막 서버 백업이 없거나 2시간 넘으면 노란 경고(업로드는 막지 않음).
3. "시드 이력" 버전 태그·메모 입력 → [서버 확인 후 업로드] → 평소대로 업로드.
4. 완료 화면 "DDA 시드 이력 저장: <id>" 확인.

**문제 시 되돌리기**
1. [백업 목록] → 업로드 직전 백업 행의 [복원 미리보기]
   (또는 시드 이력 패널의 그 업로드 스냅샷 [이 시점으로 복원 미리보기] — 그 업로드가 바꾼 열만).
2. (선택) 레벨 범위 / 업로드 스냅샷 id 로 범위 좁히기 → [미리보기] (현재 서버 읽기 1회, 쓰기 없음).
3. 되돌릴 행 수 · 열별 개수 · 대표 diff · 경고 확인.
4. 체크박스 + 확인 문구 `복원` 입력 → [복원 실행] → 검증 일치/불일치/실패/차단 확인.

## 복원 규칙
- 바뀐 열만 보낸다(보내지 않은 열 = 서버 값 유지, READBACK_RULES "unsent"). id·idx·etime 은 보내지 않는다.
- 쓰기는 `GBoostClient.update_existing_level`(new=0 1회, `<id>=upt` 확인, new=1 폴백 없음).
- 실행 직전 행마다 strict 재조회 → 미리보기 때와 다르면 그 행 차단. 쓰기 후 재조회로 검증.
- 행 삭제·새 행 생성 안 함 → 업로드로 생긴 행/서버에서 사라진 행은 목록으로만 알림(수동).
- 값 표현: `""→""`, 정수→정수 문자열, map 객체, 시드 문자열, backgroundIndex/tileSkin null←`"0"`,
  rewardList null←`"[]"` 만 실측 규칙. 그 외(다른 열의 null 등)는 '미확인'으로 표시하고 기본 제외.
  (10-28 readback 2,560행 전 열 점검: 미확인 0건)
- 시드 게이트(새 시드는 판정 근거 필요·빈 값으로 지우지 않음)는 업로드 경로 규칙이다. 복원은 서버가 예전에 실제로
  갖던 값으로 되돌리는 것이라 별도 경로로 분리했다(업로드 게이트는 그대로).
- 파일에서 가져온 백업(예 10-28 readback)은 그 뒤 서버 변경을 덮어쓸 수 있어 경고가 뜬다.
