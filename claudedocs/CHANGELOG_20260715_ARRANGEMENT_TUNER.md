# 난이도 미세조절 — 색 재배치 튜너 (Arrangement Tuner)

> 2026-07-15 · 재생성 없이 타일 '색 순서'만 재배치해 목표 클리어율에 근접시키는 독립 도구.

## 배경 / 문제
- 기존: 프로덕션 레벨 난이도가 목표와 안 맞으면 **모양째 재생성**(느림, 매번 새 모양) → target 근처서 요동 + **보스 손그림 모양 상실**.
- 통찰: match-3-collect 난이도는 **같은 색 3개를 dock(7슬롯) 넘치기 전에 모으는 난이도**. 색이 뭉치면 쉬움, 흩어지면 어려움. → **색 배치만 바꿔도 난이도 조절 가능**.

## 핵심 원리
- 레벨의 **모양·층·기믹 고정**, 필드 타일 **색(t1~15)만 위치 간 순열(permutation)** 로 재배치.
- **불변식**: 색 멀티셋 순열 = 타입별 개수 불변 → **÷3 자동 보존**. 속성(chain/grass/ice/bomb)은 위치 고정, 색만 재배치. key(t16)/컨테이너(craft/stack)/t0 제외.
- **노출순서(reveal wave)** 계산(홀짝 커버 규칙 `FindAllUpperTiles` 정합) → 같은 색을 노출순 뭉침(쉬움)~분산(어려움) K단계 + 랜덤 순열로 후보 생성 → 기존 **RL로 평가**, target 최근접 선택.
- **검증 = 순차검증과 동일 RL**(`_parallel_point_sweep` + `population_clear_rate`, skill_mean·scale) 재사용 → 튜너 통과 == 순차검증 통과 (이중잣대 없음).

## 구현 (4단계, 완료)

| 단계 | 내용 | 파일 |
|---|---|---|
| 1 | 백엔드 엔드포인트 `POST /api/tune/arrangement` + 함수(reveal/배치/튜닝) | `backend/app/api/routes/tune.py` (신규), `app/main.py`(라우터 등록) |
| 2 | 단일레벨 검증 (색배치 스펙트럼·÷3·모양보존) | — |
| 3 | 프론트 "🎚️ 미세" 버튼 (레벨 행) + `handleTuneLevel` | `frontend/.../ProductionDashboard/index.tsx` |
| 4 | 순차검증 통합 (첫 실패 시 색조절 우선 → 근접 못하면 재생성 폴백) | 동상 (handleSequentialProcess) |

**분리성**: 1~3단계는 기존 생성 파이프라인 **무수정·완전 독립**(신규 엔드포인트+버튼, 기존 레벨에 온디맨드 작동). 4단계만 순차검증 접촉(가드로 격리, 미적용시 기존 동작).

## API
```
POST /api/tune/arrangement
{
  "level_json": {...},                 # 이미 생성된(명시색 t1~15) 레벨
  "target_difficulty": 0.25,           # (a) 난이도 → 순차검증 산식으로 클리어율 변환
  "target_clear_rate_scale": 0.65,     # 보스=0.5/0.65 등 (순차검증 정합)
  "target_clear_rate": 0.4,            # (b) 클리어율 직접 지정(대안)
  "skill_mean": 0.5,                   # 순차검증과 동일값 사용 권장
  "candidates": 6                      # block 스펙트럼 단계 수(+랜덤 4 자동)
}
→ { tuned, best_level_json, predicted_clear_rate, original_predicted,
    target_clear_rate, candidates:[{block,predicted_clear_rate}], field_tiles, color_types, elapsed_ms }
```

## 사용법 (레벨 생성자)

### 단일 레벨 미세조절 (수동)
1. 프로덕션 대시보드 레벨 행에서 **🎚️ 미세** 버튼 클릭
2. 색만 재배치 → 목표 클리어율 근접 배치 자동선택 → 저장(모양 동일)
3. 알림: `Lv.X 미세조절: 24% → 42% (목표 40%, 모양 동일)`
4. 재검증 대상(verified=false)으로 표시 → 순차검증이 확정

### 순차검증 자동 (통합)
- 레벨 검증 **실패 시**: **① 색조절 우선**(목표 ±12%p 근접 가능하면 적용, 재측정) → **② 안 되면 재생성**
- → 배치로 목표 도달하는 대부분 레벨은 **재생성 없이** 통과 → 속도↑, 보스 모양 보존

## 검증 결과 (실측)
| 레벨 | 목표 | 원본→best | 달성범위 | 판정 |
|---|---|---|---|---|
| L100 보스 | 0.40 | 0.24→0.42 | 0.23~0.53 | ✅ gap 0.02 |
| L120 보스 | 0.39 | 0.25→0.39 | 0.19~0.74 | ✅ gap 0.00 |
| L50 보스 | 0.43 | 0.01→0.65 | 0.00~0.83 | ⚠️ 양극화 지형(중간없음)→배치로 못맞춤, 재생성 폴백 |

- **모양·÷3·기믹 보존** 검증: 위치 동일 / 색별 개수 동일(÷3) / 속성 위치별 동일 / 층수 동일 — 전부 True
- 속도: 후보 병렬 RL 스윕 1회(~6~18s) — 재생성 반복보다 쌈

## 한계 (정직)
- 배치 난이도는 **모양·종류수가 정한 범위** 내. 범위 밖 목표는 종류수(기존 레버)·재생성 필요.
- **양극화 지형**(L50처럼 arrangement가 easy/hard로만 갈리고 중간 없는 모양)은 목표 명중 불가 → 순차통합이 **재생성 폴백**(가드).
- 정밀도 하한 = RL 측정 노이즈(±2~3%p) — 그 이하는 무의미.

## 향후 (선택)
- 달성범위 프로브(사전 min/max 표시), 후보 refinement(best 주변 스왑), 생성 파이프라인 2단계화(전체 t0 → 난이도최적 색베이크).
