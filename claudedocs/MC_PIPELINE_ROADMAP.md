# 몬테카를로 기반 레벨 생성 파이프라인 로드맵

> 2026-06-11 작성. 기존 프로덕션 파이프라인은 그대로 유지하고,
> RL 시뮬레이션(몬테카를로 스킬 스윕) 위에 새 생성 파이프라인을 단계적으로 구축한다.

## 배경: 측정에서 확인된 문제 (500레벨 실측)

| 문제 | 증거 |
|------|------|
| 계단형 곡선 | 기믹 등장(Lv.31+) 후 k=5~7 — θ₀ 왼쪽은 0%, 오른쪽은 100% (전부 아니면 전무) |
| 언클리어러블 20% | 101/500개. 기믹 해금 레벨(60)부터 시작, 보스(x0)·특수(x9)에 집중 |
| 난이도 평탄화 | Lv.31~500 측정 난이도(1-AUC)가 ~0.52-0.58 고정. 목표난이도 노브가 안 들음 |
| 30→31 절벽 | 0.24 → 0.47 점프 (S→A 등급 경계의 생성 설정 계단) |

**원인 분석**: 기믹은 "인지하면 통과, 못 하면 막힘"의 이진 게이트라 곡선을 계단으로 만든다.
맵 모양·레이어 수는 난이도 위치(θ₀)를 옮기는 레버이고, 곡선 기울기(k)를 완만하게
만드는 레버는 기믹 종류/개수/배치다.

**설계 원칙**: 측정기가 θ₀(난이도 위치)와 k(실력 민감도)를 분리해서 제공하므로,
생성 목표도 스칼라 난이도 하나가 아니라 **목표 곡선 (θ₀, k)** 이어야 한다.

## 지표 정의 (mc_difficulty.py)

- **1-AUC**: 스킬→클리어율 곡선 아래 면적의 보수. 강건한 연속 난이도 점수 (메인)
- **θ₀**: 로지스틱 피팅상 클리어율 50%가 되는 스킬 지점 (난이도 위치)
- **k**: 로지스틱 기울기 = 실력 민감도. 높으면 절벽(계단), 낮으면 실력 무관(운빨)
- **운빨 의심**: θ₀∈[0,1]인데 ΔP=P(0.9)-P(0.15)<0.25
- **언클리어러블 의심**: 전 스킬 클리어율 ~0%

## 단계별 로드맵

### 0단계 — MC 탐색 루프 (현재 구현 단계) ✅ 목표
기존 생성기를 후보 공급원으로, MC 측정을 목적함수로 쓰는 generate-and-test:

```
목표 곡선 (θ₀*, k*) 입력
→ 기존 생성기로 후보 N개 샘플 (grid/layers/gimmick_intensity/난이도 파라미터 변주)
→ 정적 체크 (타일 3배수 등) 통과만
→ [스크리닝] 저예산 스윕: 스킬 3지점 × 8롤아웃 (~1초/후보, 병렬)
→ 상위 K개만 [풀 측정]: 8지점 × 40롤아웃 (병렬)
→ score = w1·|θ₀-θ₀*| + w2·|k-k*|/10 (+ 1-AUC 타겟 시 가중 합산)
→ 최소 score 후보 채택, 허용오차 이내면 조기 종료
```

- 멀티 피델리티(싼 평가로 거르고 비싼 평가로 확정)가 속도 핵심
- API: `POST /api/rl-sim/search`, UI: RL 시뮬레이션 탭 내 "곡선 타겟 탐색" 섹션
- 산출물: 목표 곡선에 맞는 레벨 + 후보별 측정 트레이스(→ 1단계 데이터셋의 씨앗)

### 1단계 — 민감도 데이터셋 (노브→곡선 효과 지도)
조정 요소(템플릿 모양, 레이어 수, 기믹 종류/개수)를 한 축씩 변주하며 측정.
"기믹 1개 추가 = θ₀ +0.08, k +1.2" 같은 정량 지도를 축적.
0단계 탐색 트레이스가 부산물로 쌓임. 향후 학습 기반 생성기의 훈련 데이터.

### 2단계 — 템플릿 자동 생성 (절차적 생성 + 평가 필터)
4×4~8×8 모양+레이어 배치 자동 생성:
- 대칭 패턴/노이즈/셀룰러 오토마타로 모양 후보 대량 생성
- 정적 체크(3배수, 연결성, 레이어 정합) → MC 측정으로 곡선 프로파일링
- **측정값 라벨이 붙은 템플릿 라이브러리**로 축적
- ML 도입은 1단계 데이터셋이 쌓인 뒤 검토 (처음부터 ML 불필요)

### 3단계 — 기믹 배치 최적화 (계단 곡선의 실제 해결)
템플릿+레이어로 θ₀를 잡은 뒤, 기믹 종류/개수/위치를 국소 탐색
(언덕오르기/담금질: 배치 1개 변경 → MC 재측정 → 개선 시 채택)으로 목표 k에 맞춤.
"고수만 통과하는 게이트 3개" 대신 "중수도 절반쯤 뚫는 완만한 장애물 5개" 구성 탐색.

### 4단계 — 통합: 곡선 타겟 기반 신규 파이프라인
레벨 번호 → 목표 곡선 스케줄 (θ₀ 완만 상승, k ≤ 6 유지, 보스 θ₀ +0.1)
→ 템플릿 라이브러리 선택 → 기믹 최적화 → 풀 측정 통과 시 출고.
기존 프로덕션 파이프라인과 병행 운영하며 품질 비교.

## 0.5단계 — 배치 측정 → 부적절 레벨 자동 교체 (Auto-Repair)

> 0단계 탐색을 배치 시뮬레이션과 결합한 자동화. RL 탭에서 검증 후 프로덕션에 이식.

### 흐름
```
[1] 배치 스윕 (기존 기능) — 범위 측정 → 레벨별 θ0/k/1-AUC
[2] 판정 — "부적절 레벨" 자동 표시 (사유 라벨):
    a. 언클리어러블 의심 (전 스킬 ~0%)
    b. 난이도 이탈: 목표 스케줄 θ0(n)에서 허용 밴드(±0.10) 초과
    c. 계단 과다: k > 상한 (기본 8)
    d. 운빨 의심 (luck_suspect)
[3] 교체 탐색 — 부적절 레벨마다 /rl-sim/search 호출
    (목표 θ0 = 스케줄값, 목표 k = 기본 4~5, 후보 16, 미달 시 후보 32로 1회 재시도)
    순차 루프 + 진행도/중단 (search 내부가 이미 프로세스 풀 병렬)
[4] 검토 — 기존 vs 신규 비교 테이블 (θ0/k/1-AUC/곡선), 레벨별 체크박스
[5] 적용 — 선택된 레벨만 IndexedDB ProductionLevel 교체
    (자동 덮어쓰기 금지 — 항상 사용자 승인 후 적용)
```

### 목표 난이도 스케줄 (MVP)
- UI에서 2점 선형 보간: (시작 레벨, 목표 θ0) → (끝 레벨, 목표 θ0) + 허용 밴드 ±0.10
- 보스(x0) 보정 옵션: 목표 θ0 +0.05
- 후속: 실측 분포 기반 이동 중앙값 추세선 자동 스케줄

### 교체 시 메타 처리
- `meta.mc_measurement = {theta0, k, difficulty_score, classification, measured_at}` 기록
- `regenerated=true`, `verified/verification_passed` 리셋 (기존 봇 검증과 불일치 방지)
- 이전 레벨 원본은 교체 직전 1세대만 `meta.mc_replaced_backup`에 보관 (롤백용, 옵션)

### 구현 순서
1. 프론트 판정 로직 + 결과 테이블 "부적절" 뱃지/사유 + 스케줄 설정 UI
2. 자동 교체 루프 (순차 search + 진행도/중단) + 비교/승인 테이블 + 선택 적용
3. 소범위 테스트 (예: 55~65 — 언클리어러블 Lv.60 포함 구간)
4. 검증 후 프로덕션 이식: ProductionDashboard에 "MC 기반 일괄 보정" 기능 추가
   (기존 봇 3종 검증 파이프라인은 무수정 — 별도 버튼/옵션으로 병행)

### 리스크
- 고난이도 구간에서 search 미달 가능 → 후보 수 확대 재시도, 그래도 미달이면 "근사 후보"로 표시하고 승인 판단은 사용자에게
- 교체 레벨은 새 randSeed/모양 — 기존 템플릿과 시각적 일관성 미보장 (승인 단계에서 확인)
- 레벨당 10~25초 × 대상 수 (예: 101개 ≈ 20~40분) — 진행도/중단 필수

## 병행 과제 (로드맵 외)

- **정적 데드락 필터**: 위상정렬 Greedy Peeling + key/lock 사이클 감지(Tarjan).
  언클리어러블 101개를 시뮬 없이 분류. 우선순위 높음.
- **θ=0.45 딥 진단**: 보간 봇의 체계적 비단조 구간. 0.30~0.60 정밀 스윕으로 원인 특정.
- **실유저 캘리브레이션**: 라이브 데이터 축적 후 θ₀ ↔ 유저 percentile 분위수 매핑.
