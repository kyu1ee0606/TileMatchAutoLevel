읽는 법(확정 아님):
- RSS는 **실메모리에 올라와 있는 양**만 센다. 압축·스왑으로 내려간 메모리는 빠진다. 압축기 15.5 GB·스왑 52 GB가 큰 상태라, Unity 1.05 GB처럼 작게 보이는 프로세스도 실제 사용량은 더 클 수 있다(과거 Unity 약 10GB와 직접 비교 불가).

- 이 측정 시점에 저구간모델 세션의 무거운 계산은 실행 중이 아니었다(분석 스크립트 종료 후).

## 3. 재시작 후 비교 절차 (같은 명령·같은 단위)
측정 스크립트(읽기 전용, 위 2절과 동일 — 결과를 이 문서 4절에 추가):
```
date '+%Y-%m-%d %H:%M:%S %Z'
sysctl -n hw.memsize
memory_pressure | tail -3
vm_stat                       # 페이지 16,384 B로 GB 환산: free/active/inactive/speculative/wired/compressor
sysctl vm.swapusage
df -h /
ps -axo rss=,comm=            # 2절과 같은 이름 패턴으로 합산 (Unity/Chrome/Firefox/uvicorn/python/node/claude/fseventsd/VSCode/기타)
ps -axo rss=,command= | grep -i cc-web | grep -v grep
```
| 단계 | 시점 | 측정 |
|---|---|---|
| ① | 재시작 직후, 개발 도구(Unity·cc-web·에디터 백엔드·브라우저 탭 복원) 실행 **전**, 로그인 후 약 2분 안정 대기 | 위 명령 1회 |
| ② | 사용자가 Unity·cc-web 등을 **평소처럼** 실행하고 약 10분 지난 뒤 | 위 명령 1회 |
| ②-스왑 | ② 직후부터 **10분** 동안(관찰 시간 고정) | `sysctl vm.swapusage`를 시작·종료에 1회씩 → 사용량 증가분(MB/10분). `vm_stat`의 Swapouts 누적값 차이도 함께(페이지 × 16 KB) |
- 비교 시 함께 적을 것: 실행 중인 Unity 인스턴스 수, cc-web 세션 수, 봇 측정·DDA 등 무거운 계산 실행 여부(실행 중이면 그 사실 표기 — 측정값 해석이 달라짐).
- 판단 보류 원칙: 한 번의 값으로 "부족/충분"을 정하지 않는다. ①→② 증가분, ② 10분 스왑 증가분, 이전 측정 시 측정 프로세스 수 제한(2개 이하) 조건을 함께 보고 사용자와 결정.
