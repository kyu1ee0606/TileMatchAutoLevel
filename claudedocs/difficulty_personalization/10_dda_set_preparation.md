## 0. 요약 (파일럿 30레벨)
1. **게이트 통과**: 불변 조건 위반 0, dotnet 골든 대조 불일치 0(평가한 후보 보드 전부, 변형 칸 포함).
2. **커버리지가 매우 낮다**: 변형 확보 **3 / 24**(평가 가능 기준, 전부 5단계·solver strict: Lv55·95·385). 변형 없음 21, 평가 불가 6.
3. **원인 = 제안 임계값 "h2 예측 클리어% ≥ 20"**: 에디터 예측기로 본 **원맵 자체가 24레벨 중 19레벨에서 20% 미만**(0.001~0.632, 중앙 약 0.08)이다. 원맵보다 어려운 h2가 20% 이상이어야 한다는 조건은 대부분 레벨에서 동시에 만족할 수 없다.
   - 예측기는 실력 분포(θ 0.47 중심)로 가중하는데, 이 구간이 봇 실력 골짜기 결함(06 §7-1)에 걸려 전반적으로 낮게 나온다. 적응형 θ에서 원맵 W는 0.33~0.78이다.
4. **h2 하한별 확보 수(같은 데이터 재선별, 추가 측정 없음, 평가 가능 24 기준)**:
   | h2 하한(예측 클리어%) | 확보 |
   |---|---|
   | ≥ 0.20 (지시 제안값) | **3** |
   | ≥ 0.10 | 6 |
   | ≥ 0.05 | 10 |
   | ≥ 0.5 × 원맵 예측값(상대) | **12** |
   | 예측 하한 없음(최고 측정점 ≥0.10만) | 18 |
5. **본 실행 보류(결정 대기)**: 지금 임계값으로 L32~1500을 돌리면 약 45~60시간을 써서 커버리지가 약 10% 수준이 될 것으로 추정한다.

## 1. 방식 (구현)
| 항목 | 내용 |
|---|---|
| 대상 | L32~1500 중 보스(N%10==0)·기믹 튜토리얼(51·81·111·151·191·241·291·391·441) 제외 = 정본 b'③ 비대상 |
| 준비 불가 | key 타일 레벨(슬롯 잠금 key의 t0 규칙 미지원), count-only 컨테이너 레벨(원맵 자체가 런타임 랜덤이라 고정 기준 없음) → 행 없음 + 사유 |
| 주 산출 `seedvar_N` | 원래 행(GB 변환 출력, etime 제외) 복사 + `map` = t0화 사본(정규 키 순서) + `randSeed` = 토큰 `e2\|e1\|h1\|h2`(5단계) 또는 `e2\|h2`(3단계), 토큰 = `seed` 또는 `seed@utc` + `useTileCount` = utc0. 원래 `level_N` 무변경 |
| 부 산출(참고·정본 아님) | 같은 선별의 e2·h2를 명시 타일로 구운 `easy_N`·`hard_N`(`reference_baked/`). useTileCount = 실제 종류 수(inner 포함), difficulty = 예측 클리어% × 100 |
| 평가 기준 | **원래 맵**(§V2-9-2 ④). 원맵 스캔(8θ × 64판) → 원맵 성공률이 0.5에 가장 가까운 θ 2점(골짜기 [0.34, 0.50) 제외). 스캔 최대 <0.10이면 평가 불가 |
| 후보 | utc0 풀 32 → 64 → 128, 실패한 쪽만 ±1 풀(쉬움 utc0−1, 어려움 utc0+1) 32 → 64. 1단계 64판/θ, 2단계 950판/θ |
| 견고 측정 | 추가 θ 1점 + AVERAGE + EXPERT(판정), 저스킬 θ(0.29/0.15/0, 경고만), 각 600판 |
| 선별(제안값) | 바깥 e2/h2: \|Δ\| ≥ 0.10, 독립 CI 하한 >0, 견고 통과(정보 있는 점의 2/3 이상 방향 유지 + 스킬 민감 제외), 목표 근접(e2 +0.15 / h2 −0.20). h2: 예측 클리어% ≥ 0.20 + max(θ 상한, EXPERT) ≥ 0.10. 안쪽 e1/h1: Δ ≥ 0.04 + CI + 견고, \|안쪽\| ≤ \|바깥\| − 0.02 → 양쪽 다 있으면 5단계, 아니면 3단계 |
| 해법 등급 | 솔버 PROVEN_SOLVABLE(노드 5,000)이고 솔버 미신뢰 기믹(bomb/curtain/frog/teleporter/unknown)이 없으면 strict, 아니면 봇 승리가 있으면 extended |
| 불변 조건 | 보상·rewardList·tileSkin·backgroundIndex·autoCollectCount·timea·unlockTile·col/row/num/sets/layer 원본과 같음, structHash 같음(기믹 종류·위치·개수·컨테이너 모양 = 첫 등장 레벨 같음), 레이어 연속, 정규 키 순서, (구운 행) 종류별 3배수·useTileCount = 실제 종류 수 |
| 재사용 | 파일럿 30레벨은 eval2/3/4 측정(같은 시드 풀·θ 규칙·봇 시드 기준값·판수)을 캐시로 재사용 |
| 정본과 다른 점 | 정본에 크기 기준이 없다 → 위 임계값은 전부 **제안값**(사용자 결정 항목). 토큰 문법은 PERSONALIZATION 10/02 결정(`seed@utc`)을 따랐다 |

## 3. 결정 필요 (본 실행 전)
1. **h2 하한**: 절대 20%(현 제안)는 사실상 불가능하다. 대안:
   - (a) **상대 하한 예측 ≥ 0.5 × 원맵 예측값 + 최고 측정점 ≥0.10** (권고: 12/24)
   - (b) 절대 5~10%(6~10/24)
   - (c) 예측 하한 없이 최고 측정점만(18/24)
   - 근거: 예측기는 결함 구간 가중이라 절대값 해석이 어렵다. 같은 레벨 안에서 원맵 대비 비율로 보는 편이 안전하다.
2. 범위·시간: 결정한 하한으로 L32~1500 본 실행(약 40~55시간 추정, 구간 3개로 나눔). 또는 평가 가능성이 높은 32~1000 우선.
3. 예측 클리어% 순서 위반(예측기 기준 easy > normal > hard)을 행 생성의 차단 조건으로 둘지, 경고만 둘지.
