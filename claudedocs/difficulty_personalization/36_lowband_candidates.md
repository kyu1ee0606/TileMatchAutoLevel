## 2. 후보 (사전 등록 — 결과 보기 전)

### 2-0. 전제
- **실제값 조건 편향(K1 지표)의 성질**: 예측이 E[실제 | 예측]에 맞게 보정돼 있어도 R²<1이면 "실제가 낮은 레벨"에서는 반드시 과대예측이 나온다(평균회귀). 따라서 K1 개선은 ① 순위 정보가 늘어서(좋음) ② 분포를 늘려서(개별 오차 증가 가능) 둘 다로 생긴다. ②를 막으려고 전체·고구간 MAE(K2·K3), 큰 오차 빈도, **예측값 구간별 편향**(운영 시 알 수 있는 쪽)을 함께 본다.
- 적용 여부·보정은 **신규 맵에서 알 수 있는 특징·예측값만** 쓴다. 학습 가중치는 학습 레벨의 실제값(학습 라벨)을 쓰되, 예측 시점 입력은 기존과 동일.
- 80% 범위(CQR)는 점예측 모델과 독립(분위 GBM)이다. 모든 후보에서 **범위 계산은 바꾸지 않는다**(같은 학습 데이터면 범위가 동일 — 포함률 차이는 데이터 차이에서만). 범위를 넓혀 포함률을 올리는 후보는 없다.
- 순수 파이썬 이식: W·X·S 모두 서빙 시 추가 연산이 없거나(가중치는 학습에만) 곱셈 1~2개(X 특징)·affine 1개(S)라 `model.py` 수준에서 이식 가능.

### 2-2. 봉인 평가 데이터 (튜닝 미사용)
- D394의 맵 그룹(각 레벨이 단독 그룹 — 33 §12-0 확인 "547레벨 547그룹", 스크립트가 다시 단언)을 실제값 층 3개(<0.85 / 0.85~0.96 / ≥0.96)로 나눠 층마다 round(20%)를 `RandomState(20261016)` 순열로 **봉인**. 층화는 봉인 집합에 저구간이 들어가게 하려는 분할 목적일 뿐, 모델 선택·적용에 쓰지 않는다.
- 튜닝(α, full/half 선택)은 **개발 집합(D394 − 봉인)** 의 맵 그룹 5겹 × 4반복(`RandomState(300+rep)`) OOF로만 한다. 봉인 레벨은 튜닝에 쓰지 않는다.
- 봉인 평가: 각 최종 후보를 (그 데이터 ∩ 개발 집합) 전체로 1회 학습해 봉인 레벨 예측, 비교 대상 B0도 (D379 ∩ 개발 집합)으로 같은 방식. 봉인 <0.85는 약 11레벨이라 이것만으로 개선을 확정하지 않는다(방향 일치 확인용 K5).
- 주의: 아래 주 비교(K1~K4)의 5겹×4반복 교차검증은 봉인 레벨도 포함한 기존 폴드를 그대로 쓴다(33과 같은 비교 조건). 튜닝 결과가 그 교차검증 데이터와 겹치므로 **주 비교 수치는 "오프라인 재현(튜닝 데이터 포함)"** 이다. 봉인 평가도 기존 맵(같은 분포)의 일부라 **독립 검증(신규 맵)이 아니다** — 독립 검증은 35 §6 E3/E4 신규 맵에서만.

### 2-3. 튜닝 규칙 (개발 집합 OOF, 후보 W·S만)
- 각 설정의 Δ = 설정 − (기존 방법, 같은 개발 데이터). 허용 집합 = 개발 ≥0.96 ΔMAE ≤ +0.0010 인 설정. 허용 집합이 있으면 그중 개발 <0.85 Δ편향이 가장 작은(가장 음수) 설정, 없으면 개발 ≥0.96 ΔMAE가 가장 작은 설정. 선택은 D394 개발 집합에서 한 번만 하고 D379에도 같은 값을 쓴다.
- 튜닝 설정 총 5개(W 2 + X 1 + S 2) + 기존 방법 1 = 개발 OOF 6회. **이후 추가 설정·재튜닝 없음.**

- **주의(§15와 수치 차이)**: 문서 33 §15-1은 활성 모델을 **전체 학습 모델**로 서빙한 값(q_hi 고정 → 위 끝 항상 1 → B0 합격 0)이다. 여기는 폴드 OOF라 일부 폴드의 q_hi가 퇴화하지 않아 B0도 2개가 나온다 — OOF 진단은 서빙 구조를 그대로 재현하지 않는다. 서빙 기준으로 보면 모든 후보의 전체 학습 q_hi가 고정(§5-1)이므로 위 끝은 항상 1.0이다.
- 그래도 영역이 생기는 경로는 하나: 오차표에서 **예측 0.88–0.92 구간이 high error를 벗어나면**(C2·X-D394·S) 게이트 하한이 0.92 → 0.88로 내려가 띠 안 예측이 통과할 수 있다(위 끝이 1이어도 예측이 띠 안이면 P ≥ 0.5 가능). 즉 이 후보들은 85% 합격 영역을 **만든다**(OOF 기준 15~26레벨). 그러나 이 셋은 모두 §4-3에서 고구간 악화로 **기각**이고, 합격 영역 생성은 오차표 수치 변화에서 온 것이지 0.85 근처 정확도 검증이 아니다(0.85–0.92 실제 구간 MAE는 0.036~0.041로 B0 0.040과 비슷).
- 한 줄: **채택 가능한 후보(현재 없음) 기준으로는 85% 합격 영역 없음 / 기각된 C2·X-D394·S는 OOF상 영역을 만들지만 고구간 악화 때문에 사용 불가.**

### 8-2. 위쪽 분위 머리(q_hi) 고정 원인 — 확인
1. **라벨 절단**: 목표 logit을 [0.01, 0.99]에서 자른다(`ytarget` 0.005/0.995 뒤 `residual_model.logit` 0.01/0.99). 379의 **14.51%가 정확히 절단값(4.5951)**. 0.9 분위수가 그 절단값이 된다(q0.9 = 4.5951). 0.995 절단만이었다면 4.958.
2. **기울기**: 분위 GBM 시작값 F0 = 4.5951 → 잔차 r = y − F0 ≤ 0 전부(>0 비율 0, =0 비율 14.5%). 핀볼 기울기 `where(r > 0, α, α−1)`이 **모든 행 −0.1로 동일** → 어느 분할도 이득 0 → 나무 250개 **분할 0개**, 잎 값 = 잔차의 0.9 분위 = 0. 출력이 모든 입력에서 4.5951.
3. **구현 정상 여부**: 기울기 정의(r=0을 음의 쪽으로)는 표준 구현(예: sklearn 분위 손실)과 같은 관례다 → **코드 버그 아님**. 원인은 "검열된(절단) 라벨이 10% 넘게 몰린 데이터 + 분위수 시작값"이 만드는 **학습 정체(퇴화 해)**. 폴드에서 하위표본에 절단 라벨이 10% 미만으로 들어가면 첫 잎이 음수가 되어 탈출한다(rep별 5폴드 중 1~2개, 분할 176~244개) — 고정 여부가 우연에 좌우된다.
4. **데이터·표현력 구분**: 실제로 쉬운 맵의 90% 분위가 ≥0.99인 것은 데이터 특성(타당). 그러나 어려운 맵까지 0.99인 것은 데이터가 말하는 것이 아니라 학습이 시작점에서 못 움직인 결과 — **모델 추정 실패**(표현력 부족이 아니라 최적화 정체).
5. **0.99→1.0 변환**: 범위 끝이 절단값 이상이면 1.0(아래는 0.0)으로 표시. 의미 = "이 쪽은 라벨이 잘려 알 수 없음(검열)". 영향: 포함률 처리 전 0.702 → 후 0.818(≥0.96 실제 구간 0.701 → 0.920). 실제 >0.99 레벨(6.6%가 >0.995)이 있으니 변환 자체는 검열 처리로 타당하지만, q_hi가 고정이라 **모든 맵**에서 위 끝이 1.0이 된다.
6. **CQR 폭 불안정**: 내부 점수의 80% 분위로 폭을 정하는데 폴드별 0.000~0.210 logit, 서빙 모델 0.0067. 서빙 모델의 범위는 사실상 q_lo 그대로(아래 끝)다.
7. **경로 일치**: 학습 스크립트(numpy) ↔ 서빙(`model.py` 순수 파이썬) 최대 차 1.8e-15(기존 parity). 차이는 경로가 아니라 **서빙=전체 학습 모델 / 교차검증=폴드 모델**이라는 평가 대상 차이(§8-1).

### 8-3. 목표 충족 확률 P(띠 안)의 보정 상태 (379 OOF rep 0, 서빙 `p_in_band`, 띠 = logit(t) ± 0.7)
| 목표 | Brier | ECE | P ≥ 0.5 인 맵: n / 평균 P / 실제 적중률 | P 0.9~1.0: 평균 P / 적중 |
|---|---|---|---|---|
| 0.85 | 0.126 | 0.044 | 56 / **0.715 / 0.589** | 0.961 / 0.857 (n 14) |
| 0.90 | 0.166 | 0.056 | 111 / **0.727 / 0.622** | 0.961 / **0.609** (n 23) |
| 6목표 합산(0.80~0.95) | 0.154 | 0.030 | 615 / 0.701 / 0.618 | 0.963 / 0.670 (n 94) |
- P < 0.5 쪽은 대체로 맞고, **P ≥ 0.7 쪽이 과신**(0.85에서 P 0.7~0.9 → 적중 0.30, 0.90에서 P ≥ 0.9 → 0.61). 4반복 모두 같은 방향(P ≥ 0.5: 평균 P 0.68~0.76 vs 적중 0.59~0.64).
- 서빙 전체 모델의 in-sample 보정(0.85 P≥0.5 적중 0.84)은 자기 학습 예측이라 **좋아 보일 뿐** 근거가 아니다.
- 두 조각 정규 해석: 범위 안 질량은 정의상 0.8이지만 꼬리 질량이 0.2·w / 0.2·(1−w)라 w ≠ 0.5면 10%/10%가 아니다(아래 꼬리 0.02~0.14). 위 끝이 1(검열)이면 아래 폭을 빌려 대칭(rep 0에서 278/379행). → q_hi 고정 상태에서는 P가 **아래 폭 하나**로 정해지고, 서빙 모델의 아래 폭은 CQR 폭 0.0067 때문에 좁다.
- **구조 영향**: 85% — 신뢰 게이트(예측 0.88~0.92 구간 high error)로 통과 예측이 ≥0.92 > 띠 위 끝 0.9194, 위 끝 1이면 w=0.5 → P < 0.5(33 §15 결론과 같음). 90% — 띠 [0.817, 0.948] 안 예측(0.92~0.948)은 대칭 좁은 폭 때문에 P가 크게 나온다(A90 선택 후보: 예측 0.931, 범위 [0.912, 1.0], P 0.925). OOF 보정상 P 0.9 이상이 실제로는 약 0.6만 띠 안 → **"P 0.925"를 확률로 읽으면 과대**.
- 결론: P(띠 안)는 **검증된 확률이 아니다.** 순위 점수로는 단조(P 높을수록 적중률 높음)지만 절대값은 과신이다. 문서·화면에서 "목표 충족 확률 92.5%"처럼 쓰면 안 된다.

## 9. 범위 후보 — 사전 등록 (결과 보기 전, 이 절 커밋 후 `eval` 실행)

### 9-1. 원칙
- 점예측 = 활성 모델 그대로(바이트 동일 복사). 범위만 바꿔 효과를 분리한다. 판정식(`p_in_band`, 띠 ±0.7, P ≥ 0.5)·신뢰 규칙 임계(guard)·지원 범위 규칙·표시 변환(절단 → 0/1)은 **그대로**. 신뢰도표(예측 구간별 OOF MAE·포함률)는 규칙대로 각 후보의 OOF에서 다시 만든다(포함률이 표에 들어가므로) — 표를 평가 정답에 맞춰 고르지 않는다(만드는 절차 고정: 반복 평균 OOF 점 + rep 0 범위, 기존 `evaluate`와 동일).
- 후보 2개, 하이퍼파라미터 없음(기존 값 고정). 실행 1회. 결과 후 후보·기준 변경 금지, 버그 수정 시 전체 재실행·기록.

### 9-2. 후보
| 이름 | 무엇을 고치나 | 정의 |
|---|---|---|
| **R0** | (기준) | 현행 CQR: 분위 GBM q0.1/q0.9(시작값 = 라벨 분위수) ± 내부 5겹 × 3분할 점수 80% 분위 폭 |
| **R1** | 학습 정체(§8-2 ②) | 분위 GBM의 **시작값을 점예측 OOF logit + 잔차 분위수**로: 학습 폴드 안 내부 맵 그룹 5겹(`RandomState(700+k)`)으로 점예측 OOF z를 만들고, F0 = z + Q_α(y − z). 나무·하이퍼파라미터는 기존 QGBM 그대로. 서빙: q(x) = z(x) + base + Σ나무 (z = 서빙 점예측). 그 위 CQR 폭은 R0와 같은 절차(내부 분할마다 같은 방식으로 다시 학습) |
| **R2** | 정체 + 폭 불안정(§8-2 ②⑥) | 점예측 잔차 기반 **비대칭 분할 등각(split conformal)**: 학습 폴드 안 내부 5겹 × 3분할 OOF 잔차 e = y − z를 모아 d_hi = Q_{0.9·(1+1/n)}(e), d_lo = Q_{0.9·(1+1/n)}(−e); 범위 = [z − d_lo, z + d_hi] (logit, 맵 무관 고정 폭). 나무 없음 |
- 진단 전용(판정에 안 씀, 승인 요청 근거용): **D1 경험적 P** = 같은 내부 OOF 잔차 분포로 P(z + e ∈ 띠)를 직접 센 값. 판정식 변경 제안 여부를 판단하는 참고로만 보고.

## 14. Q2 대안 기준 — 설계안 (적용·재평가 실행 금지, 승인 전 초안)

### 14-0. 검토 사유와 한계
- 사유: Q2의 비교 기준선(R0의 ≥0.96 포함률 0.944)은 R0의 위쪽 분위 머리가 모든 맵에서 0.99에 고정돼 위 끝이 항상 1.0(표시 처리)인 상태에서 나온 값이다(§8-2). R0 기준선이 "범위 추정이 잘 돼서"가 아니라 "위 끝을 구조적으로 열어 둬서" 높을 수 있다.
- 한계(명시): 이것은 **검토 사유일 뿐** 기존 Q2가 잘못됐다는 확정이 아니다. 고구간에서 위 끝을 1.0으로 두는 것이 실제로 맞는 맵도 많다(379의 14.5%가 0.99 이상, 6.6%가 0.995 초과). 이미 본 결과(R1·R2가 Q2만 실패)를 보고 기준을 고치는 것은 **사후 완화 위험**이 있으므로, 아래 대안은 (a) 승인 후 (b) 새 기준을 먼저 커밋하고 (c) §14-4의 데이터 구분을 지켜서만 쓴다.

### 14-1. 대안 기준의 구성 (모든 항목 동시 충족, 하나라도 실패 시 미제안)
| # | 항목 | 정의 | 통계적 근거 |
|---|---|---|---|
| A1 | 구간 점수(주 지표) | interval score(α=0.2, 확률 척도) 평균 Δ(후보 − R0) < 0, 레벨 짝 부트스트랩 95% 상한 < 0 — 전체 **및** 실제 구간별(아래 A3 구간) 각각 "악화 없음"(구간별 Δ의 95% 하한 > 0이면 악화) | 구간 점수는 80% 구간에 대한 적정 점수 규칙(proper scoring rule): 폭과 벗어남을 함께 벌점 → 넓히기만으로도, 좁히기만으로도 좋아지지 않는다 |
| A2 | 명목 포함률 대비 허용 편차(R0 대비가 아님) | 실제 구간 k의 포함률 c_k가 명목 0.80에서 **이항 허용 편차** 안: \|c_k − 0.80\| ≤ max(0.05, 2·√(0.8·0.2/n_k)) (n_k = 그 구간 레벨 수). 4반복 평균 포함률에 적용 | 기준선 모델의 구조적 특성(상한 고정)에 끌려가지 않도록 비교 대상을 명목값으로. n이 작은 구간은 표본 오차만큼 허용(예: n=40 → ±0.126, n=201 → ±0.056) |
| A3 | 구간별 보호 조건 | **≥0.96(n=201)**: c ≥ 0.80 − 허용편차(=0.744) **그리고** 구간 점수 악화 없음(A1) **그리고** 위 끝 1.0 비율과 실제 >0.99 레벨의 포함 여부를 따로 보고(>0.99 레벨 포함률 ≥ 0.70 — 검열 구간 보호). **<0.85(n=40)**: c ≥ 0.80 − 0.126 = 0.674 **또는** R0 대비 +0.10 이상 개선(현 R0 0.388로 둘 다 미달 가능 — 그 경우 "저구간 범위 근거 부족"으로 표시하고 제안 가능 여부와 분리 보고). 0.85–0.92·0.92–0.96: A2만 | 전체 포함률이 0.80에 가깝다는 이유만으로 모든 구간이 적절하다고 보지 않기 위해 구간마다 따로 조건을 둔다. 고구간은 검열(0.99 초과) 레벨을 따로 보호 |
| A4 | 폭 제약 | 평균 폭 ≤ 1.25 × R0 (기존 Q3 유지) **그리고** 예측 구간별 평균 폭이 R0의 1.5배 초과인 구간 없음 | 범위 과대(활용성 저하) 차단 — 포함률 상승만으로 개선 결론 금지 |
| A5 | P 보정 | 기존 Q4 유지(6목표 합산 Brier ≤ R0, P ≥ 0.5 맵의 \|평균 P − 적중\| ≤ R0) + 목표 0.85·0.90 각각 ECE ≤ R0 | 판정에 쓰는 양이 P이므로 별도 확인 |
| A6 | 봉인·외부 일치 | §14-3의 검증 데이터에서 A1(전체)·A3(≥0.96) 방향 일치 | 같은 데이터 재사용 한계 보완 |

### 14-2. R1·R2 공정 비교
- R2를 미리 채택 후보로 확정하지 않는다. R1·R2를 **같은 폴드·같은 봉인·같은 기준**으로 동시에 판정하고, 둘 다 통과하면 둘 다 보고한다.
- 둘 다 통과 시 우선순위는 사전에 고정: (1) A1 전체 Δ가 더 작은 쪽, 차이가 부트스트랩상 유의하지 않으면 (2) 단순한 쪽(R2: 나무 없음·서빙 계산 2줄)을 제안 — 단 (2)는 "동등 시 단순 우선" 규칙으로 미리 적어 두는 것이며 결과에 따라 바꾸지 않는다.
- R2의 신뢰도표 영향(예측 0.95–0.97 구간 포함률 0.716 → 그 구간 맵이 신뢰 낮음으로 바뀜, §11)은 판정 항목은 아니지만 반드시 함께 보고한다(운영 영향).
