## 1. A의 질문 두 개에 대한 답

### Q1. 두 벌 관리 비용과 최소화 방안

- [사실·문서] A는 10월 BotSimulator 변경 12커밋을 보고했다(A 「가장 큰 위험」1). 그러나 커밋당 C# 수정·검증 시간, 실패율, 실제 정책 변경 크기는 제시되지 않았다. **변경 1건당 몇 인일인지는 현재 산정 불가**다. 커밋 수를 정책 변경 건수로 간주하거나 AI의 빠른 최초 이식 시간을 반복 검증 비용으로 환산하지 않는다. (A 「패널 B에게 질문」1; 계획 §5·§8)
- [추정] 지금 최소비용 후보는 **(b) 변경 시 자동 회귀 + (c) 명시한 미지원 범위의 Python 폴백**이다. 지원 기능·규칙 버전·결과 필드 목록을 좁게 고정하고, Python 규칙 또는 프로필 변경 시 C# 회귀·지원표 갱신을 한 변경 단위로 묶는다. 변경 종류별 AI 실행비, 사람 검토 시간, 회귀 계산량, 불일치 수정 횟수를 기록해 이후 확장 비용을 추정한다. (근거: 계획 §0-A 1·5·§4-2; 조사 §1-2)
- [추정] (a) Python 동결 후 C# 우선은 장기 선택지다. 지금 적용하면 미지원 정책·solver·상태 API를 사용하는 Python이 구버전 의미를 반환하는 폴백이 될 수 있다. 정본 전환은 전체 호출처 지원 또는 명시적인 지원 종료 후에 한다. Python 폴백도 지원표와 버전이 맞아야 하며, '영구'라는 이유로 검증을 면제하지 않는다. (조사 §2-1·§2-8·§2-9; 계획 §0-A 6)
- [추정] PyPy를 폴백용으로 추가하는 것은 당장은 보류한다. 소스 중복은 줄이지 못한다(C#과 Python은 그대로 두 벌). 별도 인터프리터·프로세스·배포·동일성 검증의 운영 비용이 추가되므로, 실제 폴백 비율과 비용이 클 때 평가한다. (A 「대안 비교표」PyPy 행: 미측정·별도 워커; 조사 §3)

### shadow 기간 단축: 증거를 재사용하되 운영 관찰을 지우지 않는다

- [사실] 14만 판 기록은 코어의 특정 입력·프로필 대조이며, 현 실시간 봇 비교는 cleared 비트열 중심이고 seed=None은 skip이다. (계획 §8; backend/app/core/tilecore_bot.py:185~214)
- [추정] 고정 기간 대신 기믹·정책·시드 모드·입력 크기별 비교 완료표, 사용 응답 필드 일치, 오류·취소·재시작·큐 포화 검증을 요구한다. skip/unsupported/drop은 '불일치 없음'과 분리한다. 빈도가 낮은 경로는 고정 재현 자료로 보완할 수 있다. 장시간 누수·재시작·피크 부하처럼 시간 경과가 필요한 관찰은 남겨야 한다. 따라서 당장 며칠이면 충분하다는 숫자는 제시하지 않는다. (계획 §0-A·§3-3; tilecore_bot.py:15~26)

### 난수 상태 전달: 유망한 검증 수단이지만 일반 서비스 계약으로 바로 고정하지 않는다

- [사실] 고정 배치 경로는 초기 상태를 한 번 만든 뒤 판을 반복한다. 무시드 호출은 판마다 seed로 재설정하지 않는다. `honor_zero_seed` 경로는 판 시작 전에 임의 레벨 시드를 뽑고 초기 상태를 새로 만든다. (backend/app/core/bot_simulator.py:933~979)
- [사실] 파생 c_rng·mem_rng·style_rng는 `_play_game` 시작 시 주 RNG에서 생성된다. 따라서 **정확한 동일 시작 경계**를 잡으면 모든 파생 RNG를 개별 전송할 필요 없이 재생할 가능성이 있다. 반면 t0의 시간 시드 경로도 존재한다. (bot_simulator.py:47,1912~1943; 조사 §1-2,34행)
- [추정] 후보는 호출 진입 시 RNG 상태 + 입력 + 실제 확정된 t0 시드/초기화 정보를 기록해 배치 전체를 연속 재생하고, 차이가 날 때 판별 상태를 추가하는 방식이다. A의 판별 상태 주입은 첫 오류 위치를 찾기 좋지만 매 판 Python 상태로 다시 맞추면 이전 판의 RNG 소비 차이를 가릴 수 있으므로 **판 종료 RNG 상태 또는 배치 연속 재생**도 비교해야 한다. (근거: bot_simulator.py:962~979; A 논거 3)
- [추정] 상태 형식·버전·MT 인덱스·필요한 추가 상태와 검증 오류를 명세하고, 고정 seed/무시드/t0/조기 종료 조합의 재생을 입증해야 한다. C# Clone 지원을 외부 입력 API 지원과 동일시하지 않는다. 현재 Python 클라이언트는 `rng_seeds` 목록만 구성한다. 상태 전송을 디버깅용 선택 기능으로 제한하면 CPython 내부 표현에 대한 장기 결합을 줄일 수 있다. (backend/app/core/tilecore_bot.py:202~205; A 논거 3의 CLI 미확인 표기)

### 조기 중단: '판정 보존'과 '기존 API 보존'은 다르다

- [사실/추정] 5판 중 2승 이상이면 통과이므로 2승 또는 4패에서 **고정된 원래 5판 결과열의 bool**은 확정된다. 그러나 기존 `clear_rate`는 5판 비율이고 `avg_moves`는 실패 사유에도 쓰인다. 예를 들어 앞 4판 패배·마지막 승리인 결과열은 원래 0.2지만 4패에서 멈추면 0이 된다. (generator.py:16419~16440; bot_simulator.py:981~996)
- [사실] 이 값은 로그만이 아니다. `_ensure_no_deadlock`은 성공 시 클리어율을 반환하고 실패 후보 중 가장 높은 비율의 레벨을 보존한다. [추정] 따라서 위 0.2→0 변화는 선택되는 최선 레벨까지 바꿀 수 있다. (generator.py:16743~16755)
- [사실] `_fix_same_type_blocking`은 같은 simulator를 50개 후보에서 재사용하고 시드 인자를 전달하지 않는다. 3판 비율로 최선 시드를 선택한다. [추정] 2연패에서 멈추면 마지막 판의 승패를 몰라 0과 1/3을 구분하지 못하고, 생략한 난수 소비 때문에 다음 후보의 흐름도 달라질 수 있다. 2승 후 즉시 수락하는 좁은 최적화는 가능성이 있지만 반환·로그 계약부터 분리해야 한다. (generator.py:16280~16310; bot_simulator.py:967~990)
- [추정] 따라서 이식과 조기 중단을 동시에 바꾸지 않는다. 먼저 기존 판수·집계·RNG 흐름으로 C# 전환을 검증하고, 이후 별도 '임계값 판정' API를 설계한다. 판정과 비율 추정의 의미를 구분하고 후보 순위·반환값·난수 흐름 변경을 별도 승인된 동작 변경으로 검증한다. 현 `early_termination=True`도 최소 5판 이후의 별도 휴리스틱이므로 이 임계값 최적화와 같지 않다. (bot_simulator.py:999~1036)

## 3. 합의한 지점과 남는 쟁점

**두 1라운드 의견에서 확인되는 합의** [사실: A 입장·작업 순서, B_round1 논거 1·3·5]:

1. C# 봇 코어는 보존하고 서비스 통합을 우선한다. 생성 본체·정적 분석·다른 언어 재이식은 우선하지 않는다.
2. 작은 호출을 위한 상주 워커, 얇은 어댑터, 버전 고정, 폴백 사용률 계측이 필요하다.
3. solver·MC 전체 확장은 자동 착수하지 않고 수요를 확인한다. AI 개발 비용을 사람 인일만으로 평가하지 않는다.

**아직 A의 재응답이 필요한 쟁점** [추정]:

- 조기 중단을 첫 작업으로 삼을지: B는 기존 수치·후속 선택·RNG 흐름을 보존하는 이식 이후로 분리한다.
- RNG 상태 전달을 작은 추가 작업으로 볼지: B는 재생 경계·t0·배치 연속성·버전 계약 확인이 선행돼야 한다.
- shadow를 얼마나 줄일지: 단축 가능성에는 동의하지만 A의 폴백·사후 감시만으로 충분하다는 주장에는 동의하지 않는다.
- 전환 시점: B는 요청 단위 속도·운영 검증을 각 on 이전에 요구한다. 이 2라운드 반박을 A가 수용했다고 간주하지 않는다.

**하지 말 것** [추정·제안]:

- 조기 중단을 '결과 동일한 최적화'로 묶어 이번 이식에 섞지 않는다. 생략한 판의 성공률을 기존 고정 판수 비율로 표시하지 않는다.
- cleared 비트열 또는 지원된 표본의 불일치 0만으로 API 전체·실요청 전체가 동일하다고 선언하지 않는다.
- 단독 속도 측정을 모든 on 이후로 미루지 않는다. 이미 기록된 코어 배수를 요청 지연 배수로 대체하지 않는다.
- 수요 증거 없이 MC 전 버전·A*·PyPy 운영 경로를 추가하거나, 미지원 호출처가 남은 Python 정본을 동결하지 않는다.

## 확인 범위와 한계

[사실] A 원문 전체와 관련 Python RNG·집계·생성기 호출부를 읽었다. 난수 상태 주입 C# API, 서비스 호출량, 실시간 지연, 조기 종료 절감률은 미검증이다. C# 외부 폴더를 읽지 않았고 빌드·서버·시뮬레이션·테스트·외부 요청은 실행하지 않았다. 경로 추정으로 시도한 `routes/mc_difficulty.py` 검색은 파일 없음으로 실패했으며 MC 판단은 실제 존재하는 `backend/app/core/mc_difficulty.py`에 근거했다. 변경 파일은 이 문서 한 개뿐이다.
