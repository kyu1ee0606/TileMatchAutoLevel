# 11. 솔버 기반 지표 B(안전한 수 비율) — 구현·자동 검증

> 작성 2026-10-13 · 브랜치 `feature/pv-seed-variants` · 준비본(실험). 게임·production·원본·공유 코어 무변경.
> 코드: `backend/app/core/pv/safe_moves.py`, `backend/scripts/pv_safe_moves.py`, 테스트 `backend/tests/test_pv_safe_moves.py`(5건 통과).
> 결과: `backend/data/pv_sandbox/pv_20261002_live3/safe_moves/`(git 제외) — `plan.json`, `boards/`(K=3), `boards_k15/`, `summary_n3000.json`, `summary_n3000_k15.json`, `kcurve_n3000_k15.json`, 실행 로그.

## 0. 결론
1. **판정: B는 주 지표로 쓸 수 없다. 형식상 '보조(사전필터)' 구간이지만, 원본 대비 방향 판정은 동전 던지기(50%)보다 조금 나은 수준이다.**
   - 주 지표 (a) 평균 안전 비율: 레벨 내 Spearman 중앙값 **0.35**, 원본 대비 방향 일치율 **57%**(K=3, 신뢰 레벨 30개).
   - 사전 정의 기준은 'ρ ≥ 0.5 그리고 방향 ≥ 75%'다. 어느 지표도 통과하지 못했다.
2. 신호는 있다. 다만 약하다.
   - ρ > 0인 레벨이 23/30이다(부호 검정 p≈0.003).
   - e2를 h2보다 쉽게 판정한 레벨이 19/22(86%)다.
   - 원본을 뺀 시드끼리 순서는 봇 차이 |ΔW| > 0.2일 때 68~71% 맞는다. 0.05~0.1일 때는 약 56%다.
3. **잡음이 크다.** 경로 1개끼리의 일치도(분할 신뢰도)가 약 0.24다. 봇 W는 0.97이다.
   - K를 15로 늘려도 (a) ρ는 0.36 → 0.44에 그친다(K≈5부터 정체). 방향 일치는 56%로 그대로다.
4. **계산은 가능하다.** L1001+ 평가 불가 레벨 5개(72~135타일) × 2보드에서 10/10 모두 시작 상태 SOLVABLE이 확인됐다.
   - 보드당 중앙값 233s(52~611s), UNCERTAIN 0~9%.
   - 단, (1) 보조 수준의 신호이고 (2) L1001+에는 비교할 봇 기준이 없다. 그래서 **B만으로 L1001+ 시드를 고르는 것은 권하지 않는다.**

## 1. 정의·구현
| 항목 | 내용 |
|---|---|
| 입력 | 시드 배정 후 명시 보드(`pv_dda.lj_seed` / `lj_orig`, 선별과 같은 보드) |
| 규칙 | 코어 솔버와 같다. BotSimulator 원시함수(`_get_available_moves`/`_apply_move`/`_is_game_over`)와 `solver._state_signature`/`_remaining_count`를 import만 해서 쓴다. 이동 제한은 무력화(타일 수 + 100) |
| 시작 판정 | best-first(남은 타일 적은 순), 노드 20,000. SOLVABLE이 아니면 그 보드는 측정 불가(`root≠S`) |
| 경로 | 각 시점에서 **모든** 합법 수의 자식 상태를 판정한다(SOLVABLE/IMPOSSIBLE/UNCERTAIN, 자식당 노드 3,000). 그다음 안전한 자식 중 하나를 **균등 무작위**로 골라 진행한다. 이것을 K개 경로에서 반복하고 평균한다(시드 고정) |
| 캐시 | SOLVABLE: 증거 경로 위 상태 전부. IMPOSSIBLE: 소진 탐색에서 방문한 상태 전부. UNCERTAIN: 재사용만 하고 결론으로 쓰지 않음. 같은 보드 안에서 공유 |
| 지표 | (a) `meanSafe` 시점별 안전 / (안전 + 위험)의 평균 · (b) `low10Safe` 하위 10% 시점 평균 · (c) `bottle1`/`bottle2` 안전 ≤1/≤2이면서 위험 ≥1인 시점 수 · (d) `uncertainFrac` 판정 실패 비율 · (e, 추가) `log10RandClear` = log10 E[Π 안전 비율]. (e)는 '무작위로 두는 플레이어의 클리어 확률'의 불편 추정치다(UNCERTAIN은 분모에서 뺌) |
| 신뢰 플래그 | bomb/curtain/frog/teleport/unknown → `untrusted`(솔버가 턴 후처리를 하지 않음, 03 §1). craft → `craftRisk`(막혔다 풀린 재배출 미처리). 따로 집계 |
| 비용 상한 | 보드당 벽시계 300s(경로 사이에서 확인하므로 초과할 수 있음. 초과 경로는 `wallCap`), 자식 탐색 20s |
| 속도 | 프로파일 결과 시간의 78%가 코어 `_fast_copy_state`였다(블로킹 맵 set 재복사 + 캐시 문자열 재계산). 같은 결과를 내는 `fast_copy`를 모듈 안에 두었다. 블로킹 맵은 공유하고(셋업 후 변경 없음), 집힌 타일도 공유한다. 노드 처리 속도 **약 4.3배** |
| 동등성 확인 | 실레벨 80개(link/chain/grass/ice/bomb/curtain/frog/teleporter/unknown/craft 조합 전부), 무작위 진행 3,465수, 자식 비교 71,240회에서 코어 복사와 시그니처·dock·스택/craft·합법 수·플래그가 전부 같았다. 단위 테스트에도 넣었다 |

- 노드 예산 1,000도 시험했다. UNCERTAIN이 늘고(예 9%) 캐시에 결론이 남지 않아 오히려 느려졌다(40타일 보드 129s → 227s). 그래서 3,000을 유지했다.

## 2. 사전 정의 판정 기준 (본 실행 전에 고정, 지시문 기준 그대로)
- 주 지표 = (a) `meanSafe`. 나머지는 보고만 한다(여러 지표 중 좋은 것만 고르는 일을 막기 위해서다).
- '사용 가능' = 신뢰 레벨에서 레벨 내 Spearman 중앙값 ≥ 0.5 **그리고** 원본 대비 방향 일치율 ≥ 75%.
- '보조(사전필터)' = ρ 0.3~0.5. '사용 불가' = ρ < 0.3.
- 방향 일치: 원본 대비 |ΔW| ≥ 0.05(950판 × 2θ 기준 약 3σ)인 후보만 센다. 동점은 불일치로 친다.
- (참고) 중간 집계를 몇 번 봤지만 기준과 표본은 바꾸지 않았다.

## 3. 검증 표본
- 풀: L32~500 중 상태가 5단계/3단계/변형 없음이고, s2(950판 × 2θ) 후보가 8개 이상이며, 90타일 미만인 레벨 306개.
- 층화(시드 20261013): 크기 {<50, 50~69, 70~89} × craft 유무 × 6레벨.
  - 신뢰 레벨 **30개**(70~89 craft는 풀에 1개뿐).
  - 신뢰 불가(untrusted) 8개는 따로 집계.
- 레벨당 후보 **8~12개**(중앙값 12): 원본 + 선택된 e2/e1/h1/h2 + 나머지 s2 후보(대부분 선별 탈락) 무작위.
- 정답: s2의 W(950판 × 2θ). 봇 W의 분할 신뢰도(짝수/홀수 판)는 레벨 내 Spearman 중앙값 **0.97**이고, 레벨 내 W 범위 중앙값은 0.36이다. 즉 정답 쪽 잡음은 무시할 수준이다.

### 4-3. 잡음 (경로 표본) — K 늘리기 실험
- K=3에서 경로 1개 대 나머지 경로 평균의 Spearman(분할 신뢰도) 중앙값: (a) 0.24, bottle1 0.15, bottle2 0.28.
- 같은 보드를 K=15로 다시 쟀다(신뢰 레벨 중 <50타일 11개, 120보드). 앞쪽 k개 경로로 계산한 대응 비교:

| k | (a) ρ / 방향 | bottle1 | bottle2 | (e) |
|---|---|---|---|---|
| 1 | 0.22 / 51% | 0.28 / 54% | 0.09 / 60% | 0.17 / 53% |
| 3 | 0.36 / 59% | 0.33 / 55% | 0.42 / 55% | 0.31 / 60% |
| 5 | 0.42 / 59% | 0.39 / 64% | 0.42 / 67% | 0.18 / 59% |
| 10 | 0.43 / 58% | 0.53 / 67% | 0.39 / 71% | 0.39 / 60% |
| 15 | **0.44 / 56%** | 0.46 / 65% | 0.40 / 68% | 0.34 / 55% |
- K를 늘리면 조금 좋아지다가 정체한다. 상한은 약 0.45로 보인다.
- 즉 잡음만이 문제가 아니다. **B(균등 무작위 플레이어의 안전성)와 봇 W(휴리스틱 플레이어의 성공률)가 서로 다른 것을 잰다**는 쪽이 더 큰 원인으로 보인다.
- K=15 비용은 K=3의 3.5배(중앙값, 90분위 4.0배)다.

### 4-4. 판정 실패 · 신뢰 불가
- 시작 상태 SOLVABLE 확인 실패(노드 20,000에서 UNCERTAIN):
  - 신뢰 보드 **7/329(2%)**
  - 신뢰 불가 보드 **43/82(52%)**. frog/bomb/curtain 레벨 8개 중 4개는 보드가 전부 측정 불가였다(솔버 세계에서는 개구리가 멈춰 있어 타일이 영구히 막힘).
- 측정된 보드의 자식 UNCERTAIN 비율: 중앙값 0, 평균 0.6%, 5% 초과 9/361, 최대 32%.
- 범위 비율(참고, 03·10 기준): L32~500 대상 풀에서 신뢰 불가는 약 58%(259 중 149, 5/3단계 기준), craft 약 52%. **L1001+ 평가 불가 296 중 신뢰 불가 32(11%).**

## 6. 다음 단계 제안
1. **L1001+ 296레벨**: B만으로 변형을 고르지 않는다(근거: ρ 0.35, 방향 57%, ±0.1 구분 불가). 선택지는 10 §9-3 (a) 비대상 유지 또는 (c) 봇 상한 개선이 남는다.
2. B를 살리려면 **'플레이어 모델에 가중한 안전성'** 실험 1개를 권한다.
   - 균등 무작위 대신, 봇이 실제로 고려하는 상위 수(예: will_match 우선 + 상위 3개) 안에서만 안전 비율을 잰다.
   - 같은 30레벨 · 같은 정답으로 다시 검증한다. 보드 캐시가 없어 같은 비용(약 3시간)이 든다.
   - 이것도 ρ < 0.5면 B 계열은 종료한다.
3. 사전필터로 쓰는 안(32~1000 봇 측정 줄이기): 큰 차이(|ΔW| > 0.2)를 68~71%만 맞히므로, 버리는 후보에 좋은 후보가 섞일 비율이 크다. 절감 효과를 따로 검증하기 전에는 권하지 않는다.
4. craft 레벨에서 ρ≈0인 원인 분리(솔버 재배출 결함 vs 잡음)는 B를 계속 쓰기로 정할 때만 의미가 있다.
